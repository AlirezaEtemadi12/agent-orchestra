# i18n in practice

> **AUTHORITATIVE** for `ui/` language behaviour. ADR 0004 is the decision; this is how it is built.

## Routing

- `next-intl` with `localePrefix: 'always'`: `/fa/…` and `/en/…`, default `en`.
- `public/index.html` is served at `/` and redirects: the stored choice, else the first of the
  browser's languages that is `fa` or `en`, else `en`. It is the only page without a locale.
- No `proxy.ts` and no middleware: a static export cannot run them.

## Catalogues

- `lib/i18n/messages/common.{fa,en}.ts` and `features/<name>/i18n/{fa,en}.ts`; `i18n/messages.ts`
  composes them per locale.
- Persian and English always have the same keys and no empty text (a test asserts both).
- **Persian text is never machine-translated, reflowed or retyped** (AGENTS.md rule 6). A new Persian
  string is written by the owner, or copied from the plan that the owner approved.
- English is written in its own catalogue; it is a translation of the meaning, not of the words.

## Formatting and direction

- All formatting goes through `lib/i18n/formatter.ts` (an architecture test enforces it):
  dates, money, tokens, durations, percentages.
- Persian uses `fa-u-nu-latn`: the Jalali calendar with Latin digits. English uses `en`.
- No `timeZone` option is passed anywhere: the browser's zone is the user's zone.
- Direction comes from the locale (`fa` → `rtl`), set on `<html dir>`, with Radix's `Direction`
  provider for portals. Components use logical properties only.
