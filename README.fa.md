# agent-orchestra

[English](README.md) | **فارسی**

یک ارکستراتور چندایجنتی با گیت‌های کنترل برای کار نرم‌افزاری، به‌همراه یک داشبورد که نشان می‌دهد چه کرده است.

هیچ کاری مستقیم از یک پرامپت به کد نمی‌رسد. هر کار از چهار مرحله می‌گذرد:

</div>

```
plan → independent review → read-back → approval → implementation (cheap model) → verify
```

<div dir="rtl" align="right">

- **برنامه‌ریز** پلنی می‌نویسد که همه‌چیز را تصمیم می‌گیرد؛ پیاده‌ساز هیچ تصمیمی نمی‌گیرد.
- پلن را یک مرورکننده از **خانوادهٔ مدلیِ دیگر** مرور می‌کند.
- در **read-back** پیاده‌ساز، پیش از دست زدن به هر فایل، پلن را با زبان خودش بازگو می‌کند.
- **شما** صریحاً تأیید می‌کنید و نتیجه بدون commit تحویل داده می‌شود.

## چه چیزهایی در این مخزن است

| پوشه | توضیح |
|---|---|
| `engine/` | خود ارکستراتور (PowerShell 5.1): زنجیرهٔ مدل‌ها برای هر نقش، poolها و سهمیه، و یک مجموعه تست offline روی یک ایجنت ساختگی. پروژه‌ها آن را با یک shim ده‌خطی صدا می‌زنند. |
| `api/` | .NET 10 و SQLite. runها و ledgerها را import می‌کند، رویدادهای زنده را می‌گیرد و UI را سرو می‌کند. |
| `ui/` | خروجی static از Next.js 16 (shadcn/ui)، فارسی و انگلیسی، روشن و تیره. |
| `scripts/` | `publish.ps1`: اپ ویندوز را در `dist/` می‌سازد. |
| `.ai/` | دانش برای هر ایجنت: معماری، تصمیم‌ها (ADR) و قراردادها. |
| `.orchestra/` | کارِ ارکستراشده: workflow، پلن‌ها، پیش‌نمایش‌ها و ایده‌ها. |

داشبورد این‌ها را نشان می‌دهد: runها به تفکیک پروژه، هزینه به تفکیک روز و ماه و مدل و پروژه، کیفیت مدل‌ها
(تعداد دورِ رسیدن به PASS، ارزش read-back، نرخ FAIL در verify، نرخ cache hit)، پلن‌ها و یک برد زنده.
داشبورد فقط می‌خواند: چیزی را تأیید یا پیاده نمی‌کند، run را شروع نمی‌کند، و فقط از راه setup در پوشهٔ
پروژه می‌نویسد (ADR 0009). اگر داشبورد خاموش باشد، run دقیقاً مثل قبل کار می‌کند.

## راهنمای استفاده

### ۱. ساختن اپ

.NET 10 و Node 22 روی ویندوز لازم است. در ریشهٔ همین مخزن اجرا کنید:

</div>

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish.ps1
```

<div dir="rtl" align="right">

UI یک بار ساخته می‌شود، اپ single-file منتشر می‌شود، `wwwroot/` و `engine/` و `appsettings.json` کنارش
گذاشته می‌شوند و پوشه در `dist/Orchestra-win-x64.zip` فشرده می‌شود. `dist/Orchestra-win-x64/Orchestra.exe`
را باز کنید: داشبورد در پنجرهٔ خودش روی `http://localhost:3500` باز می‌شود که فقط همین کامپیوتر
می‌بیند. اجرای دوباره پیام «Orchestra از قبل باز است» می‌دهد؛ بستن پنجره اپ را می‌بندد.

داده‌های اپ در `%LOCALAPPDATA%\Orchestra\` می‌ماند: `orchestra.db`، `projects.json`، توکن گزارش و
پروفایل‌های exportشده.

### ۲. اضافه کردن پروژه

از منو «پروژه‌ها» و بعد «پروژه‌ی جدید» را باز کنید. مسیر پوشهٔ پروژه را همان‌طور که در ویندوز می‌بینید
بنویسید (مثلاً `F:\Projects\MyApp`)، یا با دکمهٔ «انتخاب» پیدایش کنید؛ در پنجرهٔ اپ دیالوگ انتخاب پوشهٔ
ویندوز باز می‌شود. فرم شناسه، نام، پوشهٔ runها و ریپوها را خودش پر می‌کند و شما می‌توانید هر کدام را عوض
کنید.

«ادامه» فهرست راه‌اندازی را باز می‌کند: هر سطر یک فایل یا کار است با برچسب «ساخته می‌شود»، «اضافه می‌شود»،
«به‌روز می‌شود» یا «هست». سطرهای دانش (`AGENTS.md`، `.ai/README.md`) اختیاری‌اند و می‌شود برشان داشت. زیر
فهرست، دستورهای build و test هر ریپو، هر کدام در یک خط، آمده و قابل ویرایش است.

«راه‌اندازی» فایل‌ها را می‌نویسد، پروژه را ثبت و import می‌کند و نتیجهٔ هر سطر را نشان می‌دهد. اجرای دوباره
امن است: همه‌ی سطرها «هست» می‌شوند و چیزی نوشته نمی‌شود. برای پروژه‌ی موجود، «بررسی راه‌اندازی» در فهرست
پروژه‌ها همین صفحه را باز می‌کند.

فقط دو چیز در پروژه‌ای که از قبل آن‌ها را دارد ممکن است عوض شود: `.orchestra/orchestrator.json` فقط وقتی
بلوک `report` ندارد آن را می‌گیرد، و `.orchestra/orchestrator.local.json` (که در git نمی‌رود) مقدارهای
`enginePath`، `profilesPath` و توکن گزارش را. به چیز دیگری دست زده نمی‌شود و هیچ‌چیز commit نمی‌شود. گزارش
دادن یک‌طرفه است: اگر داشبورد خاموش باشد، run دقیقاً مثل قبل کار می‌کند.

### ۳. اجرای یک کار

بعد از هر دستور یک خلاصه چاپ می‌شود. خط `next:` در آن می‌گوید دستور بعدی چیست.

| مرحله | دستور | چه اتفاقی می‌افتد |
|---|---|---|
| پلن | `run.ps1 new T-APP-001 MyRepo "چه کاری"` | برنامه‌ریز پلن را می‌نویسد. یک مدل از خانوادهٔ دیگر آن را مرور می‌کند، و مدل پیاده‌ساز آن را بازگو می‌کند. |
| تأیید | `run.ps1 approve T-APP-001` | شما تأیید می‌کنید و موتور شاخه را می‌سازد. |
| پیاده‌سازی | `run.ps1 implement T-APP-001 1` | یک مدل ارزان‌تر فاز ۱ را پیاده می‌کند. هیچ‌چیز commit نمی‌شود. |
| بررسی | `run.ps1 verify T-APP-001` | موتور gateهای پلن و یک مدل بررسی‌کننده را اجرا می‌کند. |
| بستن | `run.ps1 close T-APP-001` | موتور پلن را بایگانی می‌کند. commit و merge با خود شماست. |

هر وقت خواستید، `run.ps1 status T-APP-001` وضعیت را نشان می‌دهد. اگر یک hop منتظر آدم باشد (adapter دستی)،
موتور درخواست را در پوشهٔ `inbox/` همان run می‌نویسد و شما با `run.ps1 answer` جواب می‌دهید. همهٔ
دستورها، نقش‌ها و تنظیمات در [`engine/README.md`](engine/README.md) آمده است.

### ۴. دنبال کردن کارها

در «runها» فهرست runها را می‌بینید و در «تخته‌ی runها» همان‌ها را زنده. «هزینه» خرج را به تفکیک روز، ماه،
مدل و پروژه نشان می‌دهد. «کیفیت مدل‌ها» تعداد دورِ رسیدن به PASS، ارزش read-back و نرخ FAIL در verify
را نشان می‌دهد. صفحهٔ «شروع کار» در منو دو قدم دارد: اپ در حال اجراست، و اولین پروژه با رسیدن اولین
رویدادش راه‌اندازی شده است.

### اجرا از سورس

.NET 10 و Node 22 لازم است:

</div>

```powershell
cd ui; npm ci; npm run build; cd ..
```

```powershell
dotnet run --project api/src/Orchestra.Api
```

<div dir="rtl" align="right">

`http://localhost:3500` را در مرورگر باز کنید. در حالت توسعه «انتخاب» به‌جای دیالوگ ویندوز، مرورگر پوشهٔ
خود اپ را باز می‌کند. هیچ متغیر محیطی لازم نیست: داشبورد توکن خودش را می‌سازد و در `<data>/report-token`
نگه می‌دارد (پلن ۰۰۰۹). اگر `engine/` را ویرایش می‌کنید، در `appsettings.Local.json` کنار exe مقدار
`Orchestra:EnginePath` را به همان checkout بدهید تا راه‌اندازی، پروژه‌ها را به کپی منتشرشده وصل نکند.

## وضعیت

این‌ها تمام شده‌اند: فاز ۰ (import، کتابخانه، پروژهٔ جدید)، فاز ۱ (رویداد زنده)، انتقال موتور، پروفایل‌ها،
و اپ محلی که پروژه را خودش راه‌اندازی می‌کند (پلن ۰۰۱۲). کارهای بعدی جدول‌های سمت سرور (پلن ۰۰۱۰) و
کمتر کردن فراخوانی‌های `git` در موتور (پلن ۰۰۱۱) است. فازها در [`.ai/vision/roadmap.md`](.ai/vision/roadmap.md) و وضعیت
پلن‌ها در [`.orchestra/plans/`](.orchestra/plans/README.md) است. ایجنت‌ها از [`AGENTS.md`](AGENTS.md) شروع
می‌کنند.

این یک ابزار شخصی است که هر وقت زمان باشد ساخته می‌شود. issue خوش‌آمد است، ولی تعهدی برای پشتیبانی نیست.
